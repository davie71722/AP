# 竹縣大傷後送小幫手

新竹縣重大多傷事件（MCI）醫療後送決策支援工具。現場後送官在平板上點選輸入事件類型、地點、檢傷（紅黃綠黑）與救護車，系統依「傷患嚴重度 × 醫院收治能力與剩餘量能 × 車程與車輛週轉時間」即時產生派遣建議：

```
傷患代碼 ➔ 指派車輛（第 N 趟） ➔ 目標醫院｜出發 / 抵院 / 返場預估時間｜警示標籤
```

> **本系統是決策支援工具，最終派遣決定由現場指揮官／後送官負責。**

## 快速開始

```bash
npm install
npm run dev        # 開發伺服器（--host，可用平板連區網測試）
npm test           # Vitest 單元測試
npm run build      # 型別檢查 + 產生 PWA（dist/）
npm run preview    # 預覽建置結果
```

首次以瀏覽器開啟後，Service Worker 會快取全部檔案；之後**斷網也能完整啟動與運算**。建議在平板上「加入主畫面」以全螢幕執行。

## 使用流程

1. **事件**：選事件類型（可複選）、事發地點（13 鄉鎮市／國道路段／平板 GPS）→「開始」。設定裝載、交接時間、離線車程倍率、綠傷每車人數、長程門檻、保留車數、日夜容量。
2. **輸入**：紅／黃／綠／黑大按鈕，每點一次產生一個代碼（紅A、紅B…），附「−1 撤銷」。點代碼可加標籤、再檢傷改色（保留原代碼）、用數字鍵填檢傷卡號。點分隊按鈕新增車輛（車號自 91 起），車輛卡片可改「已到場／已返場／除污完成／離線／刪除」並修正 ETA。醫院自行到院人數以 ± 鈕扣除。
3. **派遣**：事件提醒置頂；建議清單中，車輛已在現場的列可按「確認出發」，其餘顯示「預排」；車應已到場但未標示時顯示「車已到場？」。提供「撤銷上一筆」。
4. **醫院**：依縣市分組，紅黃綠量能條（實色＝已用、灰＝自行到院、淡色＝建議中），一鍵關閉（Bypass）立即重算；編輯模式可調整容量、車程修正、除污能力。
5. **回報**：自動產生可複製的回報文字，完整操作紀錄可匯出 JSON／CSV。

## 演算法摘要（詳見 `src/engine/plan.ts`）

- 待送非黑傷患依紅→黃→綠、建立順序排序；未滿足事件 `dispatchRequires`（如化災未除污）者列入「待處置」。
- 綠傷依「每車人數」分組送同一家。
- 車輛可用時間：待命 0、趕赴中 ETA−已過時間、運送中 返場−現在；待除污／離線／已污染者不可用；扣除保留車（縣內最晚可用者）。
- 每個工作指派給最早可用的車（同時可用時趟次少者優先），對未關閉且量能足夠的醫院計分取最高：

```
score = 級別適配 − 車程權重 × 去程分鐘 − 25 × 已用量/總量 + 特殊加分 − 長程懲罰
```

- 化災事件：車輛運送一趟後即視為污染，返場後轉「待除污」，需手動解除。
- 警示：滿載轉向、長程後送、跨縣市、化災責任醫院、紅傷等候過久（→請求增援）。

### 權重詮釋說明

規格中「創傷事件時紅傷以 `traumaLevel` 判斷」與適配表的「中度（外傷重度能力）85」欄位有兩種解讀。目前採規格 4.2「紅傷應視同重度級處理」：創傷事件中，中醫大新竹這類醫院紅傷以重度級（100）計；非創傷事件一律以總分級 `level` 判斷。若要改用 85，將 `src/engine/weights.ts` 的 `redTraumaUsesTraumaLevel` 設為 `false`。

由於負載懲罰（25 × 已用比例）會分散量能，紅傷在附近重度級醫院接近滿載時，可能比「先填滿再轉向」更早分流到為恭等醫院；此為初始權重的設計結果，需在 Phase 4 以桌上推演校正。

## 即時車程（Google Routes API）

前端**不持有金鑰**，只呼叫代理端點：

1. 部署 `proxy/cloudflare-worker.js`（說明見檔頭），以 `wrangler secret put GOOGLE_MAPS_API_KEY` 設定金鑰，並設 `ALLOWED_ORIGIN`。
2. 複製 `.env.example` 為 `.env`，填 `VITE_ROUTES_PROXY_URL=<代理網址>` 後重新建置。
3. 金鑰以單位／專案帳號申請，只開放 Routes API；在 Cloud Console 設定每日用量上限與預算警示。

有網路且已設定代理時，系統會雙向查詢（現場→醫院、醫院→現場）以及趕赴中車輛所在分隊→現場，每 5 分鐘或地點變更時更新；失敗或離線時自動退回靜態估算，畫面標示「離線估算／最後更新 HH:MM」。

離線估算：`直線距離 × 1.35`；> 25 km 65 km/h、10–25 km 50 km/h、< 10 km 35 km/h；`3 + 路程/速度 × 60 + 山區加成`（尖石、五峰 +20；橫山、北埔、峨眉、關西 +5），再乘交通倍率並加上醫院人工修正。

## 尚未解決、需在系統外決定的事項

**醫療政策**
- 車不夠時，紅傷就近送中度／一般級穩定，還是等車送重度級？（需事先訂規則）
- 特殊族群（兒童、孕婦、重度燒傷、神經外科）的指定醫院名單

**醫院量能**
- 各院 MCI 收治量（日／夜）的事前協定
- 事件中量能由誰回報、透過什麼管道（北區 EOC／119 指揮中心）、多久更新

**車輛調度**
- 縣內需保留多少車處理其他 119 案件
- 返場車被指揮中心改派時如何回報
- 山區事件是否納入空中後送
- 大量綠傷改用大客車集體後送的啟動條件

**運作制度**
- 多台平板時的唯一資料來源：建議只有後送官那台可「確認出發」，其他台唯讀（未來再做同步）
- 系統失效時的紙本後送板格式，需與畫面一致
- 檢傷卡號與救護紀錄表的事後勾稽、家屬查詢
- 個資保護（本系統預設不輸入姓名）
- 多起事件同時發生時醫院量能共用
